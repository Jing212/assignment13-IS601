# Reflection – Assignment 13: JWT Authentication, Front-End & Playwright E2E

In Module 13, I focused on building a JWT-based user authentication system for my FastAPI application. This included creating registration and login pages, adding client-side validation, writing Playwright end-to-end tests, and setting up a GitHub Actions CI/CD pipeline to test and deploy the application to Docker Hub. Since I had already worked with user models and database operations in previous modules, this assignment helped me better understand how authentication works in a real application and how the front-end communicates with the back end.

One of the main things I learned from this module was how JWT authentication works. When a user registers, the application validates the information, checks for duplicate users, and stores a hashed password in the database. During login, the application verifies the credentials and generates a JWT token if they are correct. I also learned why both client-side and server-side validation are important. JavaScript helps users catch mistakes before submitting the form, while Pydantic validates the data on the server. I also gained more experience with Playwright by testing both successful and unsuccessful registration and login scenarios. These tests helped me understand how to verify the application from a user's perspective instead of only testing individual functions.

One of the challenges happened when my registration and login pages suddenly stopped working, even though they had worked before. After checking the Docker logs, I discovered that the users table was missing from PostgreSQL because my Playwright tests were using the same database and dropping the tables during cleanup. Restarting the web container recreated the tables and solved the issue. This experience taught me why it is important to separate the testing database from the development database.

Overall, Module 13 was challenging but helped me connect several concepts I had learned in previous assignments, including FastAPI, PostgreSQL, Docker, authentication, automated testing, and CI/CD. I realized that building the application is only one part of the process, and troubleshooting dependency issues, database problems, and pipeline failures is just as important. I also became more comfortable reading error logs and identifying the root cause instead of randomly changing the code.
